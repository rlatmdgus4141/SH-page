핵심 경험 3가지

논문만 읽지 않고, 패킷으로 프로토콜을 확인했습니다 ▸
상황과 과제
학부연구생으로서 매주 세미나 주제를 스스로 정해 발표해야 했습니다.
행동
LTE 초기 접속 절차와 5G 망 구조 등 통신 주제를 조사해 발표 자료를 만들고, Wireshark로 실제 트래픽을 캡처해 계층별 헤더를 직접 확인했습니다.
결과
프로토콜을 문서의 개념으로만 보지 않고 실제 패킷과 연결해 확인하는 습관을 만들었고, 이후 통신 문제를 계층별로 나누어 보는 분석 방식의 기반이 됐습니다.
이 경험이 보여주는 것
모르는 현상을 바로 추측하기보다, 패킷과 계층 구조를 근거로 확인하면서 범위를 좁혀 가는 방식입니다.
GNS3 통신 장애, 계층별 점검으로 Windows 방화벽까지 원인을 좁혔습니다 ▸
상황과 과제
GNS3에서 VirtualBox 기반 Rocky Linux 9 서버와 Windows 10 클라이언트를 연결해 DHCP 자동 IP 할당을 구성한 뒤, 서버에서 클라이언트로 Ping이 되지 않는 문제가 발생했습니다.
행동
인터페이스와 IP 설정을 확인한 뒤 ARP 학습 상태를 통해 L2 통신이 정상임을 확인했습니다. 이후 Windows 방화벽을 점검해 ICMP 차단을 원인으로 특정했습니다.
결과
방화벽 전체를 해제하는 대신 필요한 범위의 ICMP 인바운드 규칙을 적용해 통신을 정상화했습니다.
이 경험이 보여주는 것
장애를 한 번에 추측하지 않고, 확인 가능한 계층부터 하나씩 제외하면서 원인을 좁혀 가는 문제 해결 방식입니다.
5G 자원 스케줄링, 알고리즘을 직접 설계하고 수치로 비교했습니다 ▸
상황과 과제
캡스톤에서 5G eMBB·URLLC가 공존하는 환경의 자원 할당 문제를 다뤘고, 저는 강화학습(PPO) 기반 eMBB 스케줄링을 담당했습니다.
행동
PPO 모델을 직접 설계하고 보상 함수를 반복해서 조정하면서 기존 방식과 성능을 비교했습니다.
결과
사용자 100명 환경에서 기존 Heuristic+GNN 방식의 6.9Mbps 대비 10.4Mbps의 처리량을 확인했습니다. 결과를 논문과 포스터로 정리해 한국방송·미디어공학회 동계학술대회에서 장려상을 받았습니다.
이 경험이 보여주는 것
기대한 결과가 나오지 않을 때 모델의 결과를 그대로 받아들이기보다, 지표와 보상 함수를 다시 확인하고 비교 실험을 통해 판단했습니다.
